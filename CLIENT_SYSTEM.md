# 👤 Система регистрации и работы с клиентами

## ✅ Реализовано

### 1. **Регистрация и логин для клиентов**

#### Регистрация клиента:
```json
POST /api/auth/register
{
  "name": "Иван Иванов",
  "email": "ivan@example.com",
  "password": "password123"
}
```

**Особенности:**
- Все новые пользователи автоматически получают роль `client`
- Данные сохраняются в базе данных PostgreSQL
- Пароль хешируется с помощью bcrypt
- Возвращает JWT токен для авторизации

#### Логин клиента:
```json
POST /api/auth/login
{
  "email": "ivan@example.com",
  "password": "password123"
}
```

---

### 2. **Создание заявки с привязкой к пользователю**

#### Создание тикета (требует авторизации):
```json
POST /api/tickets/create
Headers: Authorization: Bearer <JWT_TOKEN>
{
  "message": "Не могу подключиться к Wi-Fi"
}
```

**Процесс:**
1. Система получает `userId` из JWT токена
2. Тикет автоматически привязывается к пользователю
3. ИИ классифицирует заявку
4. Если типовая → авторешение
5. Если сложная → направление в отдел с summary и черновиком

---

### 3. **Получение тикетов пользователя**

#### Мои тикеты:
```json
GET /api/tickets/my
Headers: Authorization: Bearer <JWT_TOKEN>
```

**Возвращает:**
- Все тикеты текущего пользователя
- Ответы операторов (если есть)
- Статусы и категории
- Авторешения (если были)

---

### 4. **Отправка ответа клиенту от оператора**

#### Оператор отправляет ответ:
```json
PUT /api/tickets/:id/resolve
Headers: Authorization: Bearer <OPERATOR_TOKEN>
{
  "response": "Здравствуйте! Проблема решена. Проверьте подключение."
}
```

**Процесс:**
1. Оператор видит заявку в админке
2. ИИ уже подготовил черновик ответа
3. Оператор редактирует или отправляет как есть
4. Ответ сохраняется в `messages` таблице
5. Клиент может получить ответ через `/api/tickets/my`

---

## 🔄 Полный цикл работы:

### Пример: Юзер 1 создает заявку

1. **Юзер 1 регистрируется:**
   - POST `/api/auth/register`
   - Получает JWT токен

2. **Юзер 1 создает заявку:**
   - POST `/api/tickets/create` (с токеном)
   - Описывает проблему: "Не могу подключиться к Wi-Fi"
   - Система автоматически классифицирует
   - Если сложная → отправляется в отдел

3. **Оператор видит в админке:**
   - GET `/api/tickets/complex`
   - Видит заявку от Юзера 1
   - Видит summary от ИИ
   - Видит готовый черновик ответа от ИИ

4. **Оператор отправляет ответ:**
   - PUT `/api/tickets/:id/resolve` с текстом ответа
   - Ответ сохраняется в базе
   - Тикет закрывается

5. **Юзер 1 получает ответ:**
   - GET `/api/tickets/my`
   - Видит свой тикет
   - Видит ответ оператора в поле `operatorResponse`

## 📊 Структура данных:

### Таблица users:
- `id` - ID пользователя
- `name` - Имя
- `email` - Email (уникальный)
- `password` - Хешированный пароль
- `role` - 'client' или 'operator'

### Таблица tickets:
- `userId` - Привязка к пользователю
- `message` - Текст заявки
- `category`, `department`, `priority` - Классификация
- `status` - Статус (new, in-progress, resolved, closed_auto)
- `draftResponse` - Черновик ответа от ИИ

### Таблица messages:
- `userId` - Пользователь
- `ticketId` - Привязка к тикету
- `message` - Вопрос клиента
- `reply` - Ответ (авто или от оператора)
- `isQuestion` - true для вопросов, false для ответов

## ✅ Преимущества:

5. **Автоматизация** - ИИ помогает операторам с черновиками
